# 助成金対応リスキリング動画学習システム 要件定義書

> 前提は「助成金対応リスキリング動画学習サイト」だが、実態としては
> **LMS＋受講管理＋証跡出力＋協業先成果報酬管理システム** である。

## 1. システム概要

本システムは、リスキリング研修を動画学習形式で提供し、受講者ごとの視聴状況、学習進捗、確認チェック、テスト結果、修了判定、修了証、LMS証跡を一元管理するシステムである。

厚生労働省の人材開発支援助成金は、事業主等が雇用する労働者に対し、職務に関連した知識・技能を習得させる職業訓練等を計画に沿って実施した場合に、訓練経費や賃金の一部等を助成する制度である。したがって、本システムは単なる動画配信サイトではなく、助成金申請・確認に必要な受講証跡を残せるLMSとして設計する。

## 2. 開発目的

| 目的 | 内容 |
|---|---|
| 助成金要件対応 | eラーニング研修として必要な受講管理・進捗管理・修了証跡を残す |
| 受講漏れ防止 | 未ログイン、未視聴、テスト未受験、期限切れを自動検知する |
| 運営負荷削減 | リマインド、進捗確認、証跡出力をシステム化する |
| 協業先管理 | 協業先ごとの案件、導入企業、受講者、売上、成果報酬を管理する |
| 申請準備支援 | 社労士・申請担当者が確認しやすい形式でデータ出力する |

## 3. 制度上の前提要件

### 3-1. eラーニングはLMS管理が必須

eラーニングは、情報通信技術を活用した遠隔講習であり、LMS等により訓練の進捗管理が行えるものとされている。LMSでは、修了日、受講開始日時、受講終了日時、受講時間数、進捗率等が分かる必要がある。

本システムでは以下を必須ログとして保存する。

- 受講開始日時
- 受講終了日時
- 動画ごとの再生開始・終了
- 視聴完了日時
- 受講時間数
- 進捗率
- 確認チェック日時
- テスト受験日時
- テスト結果
- 修了日
- 修了証発行履歴
- 管理者操作ログ

### 3-2. 10時間以上の訓練管理

eラーニング・通信制では、1コースあたりの標準学習時間が10時間以上、または標準学習期間が1か月以上であること等が要件として示されている。また、訓練期間中に訓練を修了することが必要であり、LMS等で実施状況を確認できない場合は対象外とされる。

コース登録時には以下を必須項目とする。

| 項目 | 内容 |
|---|---|
| コース名 | 申請書類と一致させる |
| 標準学習時間 | 10時間以上を判定 |
| 標準学習期間 | 必要に応じて1か月以上を判定 |
| 訓練開始日 | 計画届・契約期間と紐づけ |
| 訓練終了日 | 修了期限として管理 |
| 受講対象者 | 企業・事業所・部署単位で管理 |
| 修了条件 | 動画視聴、確認チェック、テスト、レポート等 |
| 助成金対象区分 | リスキリング支援コース等を選択 |

### 3-3. 修了証・LMS情報の保管

eラーニングの場合、修了証の写しやLMS情報の写し等が必要書類として示されており、LMS情報には修了日、受講開始日時、受講終了日時、受講時間数、進捗率等が含まれる。定額制サービスでは、教育訓練機関が発行する「受講時間が10時間以上である者の一覧表」が必要になる整理もある。

令和8年4月8日からの変更点では、従来提出を求めていた修了証やLMS情報の写しについて、提出不要とされる場合でも、労働局から提出を求められる場合があるため、事業所で整備・保管する必要があるとされている。

よって、本システムでは、提出の有無に関係なく証跡を保存・出力できる状態にする。

### 3-4. 価格疎明・実質無料リスクの回避

令和8年5月14日以降、人材開発支援助成金では、支給申請時に「受講料等の価格設定に関する疎明書」の提出が必要となっている。

また、厚労省資料では、助成金申請手続きの代行に関する注意、実質無料スキーム、協力金・営業協力金による実質負担軽減、AI研修費とAIツール導入費を混同するスキームについて注意喚起されている。

そのため、本システムでは以下を分離管理する。

- 研修費
- LMS利用料
- 運用支援費
- AIツール利用料
- 協業先売上
- Lカート成果報酬
- 助成金申請額・受給額

特に、Lカートの成果報酬は助成金受給額に連動させない。協業先の研修売上、LMS運用、案件管理、証跡管理支援に対する業務委託報酬として管理する。

## 5. 基本業務フロー

### 5-1. 導入フロー

1. 協業先が導入企業を獲得
2. Lカートが協業先・導入企業アカウントを作成
3. 企業専用マスターキーを発行
4. 受講対象者を登録またはCSV一括登録
5. 対象コース、受講期間、修了条件を設定
6. 受講者に招待メール・LINE等を送信
7. 受講者が初回登録して受講開始

### 5-2. 受講フロー

1. 受講者がログイン
2. コース一覧を確認
3. 動画を視聴
4. 視聴完了チェックを押す
5. 学んだこと・活かし方を入力
6. 確認テストを受験
7. 合格条件を満たす
8. システムが修了判定
9. 修了証を発行
10. LMS証跡に反映

### 5-3. 管理フロー

1. 管理者がダッシュボードで全体進捗を確認
2. 未ログイン者、未視聴者、遅延者を抽出
3. 自動リマインドまたは手動連絡
4. テスト未受験者を確認
5. 修了条件不足者を確認
6. 修了証・LMSレポートを出力
7. 社労士・申請担当者に共有
8. 不足項目を差戻し・修正

## 6. 機能要件

### FR-01 ログイン・認証機能

| 項目 | 要件 |
|---|---|
| ログイン方式 | メールアドレス・パスワード |
| 初回登録 | 招待URLまたはマスターキー方式 |
| 2段階認証 | 管理者は必須、受講者は任意設定 |
| パスワード再設定 | メール認証で再設定 |
| ログイン履歴 | IP、端末、日時を保存 |
| アカウント停止 | 退職者・契約終了者を停止可能 |

### FR-02 マスターキー・ID発行機能

| 項目 | 要件 |
|---|---|
| 企業別マスターキー | Lカート運営側が発行 |
| 有効期限 | 設定可能 |
| 利用回数制限 | 設定可能 |
| 所属企業紐づけ | マスターキーで自動判定 |
| 自由登録制限 | マスターキーなしの登録不可 |
| 再発行 | 旧キー停止後に再発行可能 |

この機能により、誰でも勝手に登録できない構造にする。

### FR-03 企業管理機能

| 項目 | 要件 |
|---|---|
| 企業登録 | 企業名、法人番号、所在地、担当者を登録 |
| 事業所管理 | 雇用保険適用事業所単位で管理 |
| 契約期間 | 開始日・終了日を設定 |
| 受講可能コース | 企業ごとに割当 |
| 管理者設定 | 企業管理者を複数登録可能 |
| 証跡出力範囲 | 自社分のみ閲覧可能 |

### FR-04 受講者管理機能

| 項目 | 要件 |
|---|---|
| 個別登録 | 1名ずつ登録可能 |
| CSV一括登録 | 氏名、メール、社員番号、部署等を一括登録 |
| 招待送信 | メール・LINE等で招待 |
| 所属管理 | 企業、事業所、部署を紐づけ |
| コース割当 | 受講者ごとにコースを設定 |
| ステータス管理 | 未登録、受講中、遅延、修了、期限切れ等 |
| 修了後編集制限 | 氏名・修了日・ログの改ざん防止 |

|---|---|

| 修了条件 | 動画、チェック、テスト、レポート等を設定 |
| 助成金区分 | 対象コースを選択 |

| 項目 | 要件 |
|---|---|

### FR-18 成果報酬管理機能

成果報酬型の場合、基本設計は以下とする。

| 項目 | 内容 |
|---|---|
| 基本報酬 | 協業先の研修売上の20% |
| 報酬対象 | 研修売上、LMS運用支援、証跡管理支援 |
| 非連動項目 | 助成金受給額には連動させない |
| 最低報酬 | 案件ごとに要相談 |
| 支払時期 | 協業先入金後、翌月末払い等 |
| 請求書 | Lカートから協業先へ発行 |
| 管理単位 | 協業先・導入企業・案件単位 |

システム上は、**助成金受給額20%**ではなく、**協業先研修売上20%**として管理する。

## 13. 最終設計方針

本システムは、以下の思想で作る。

> 動画を見せるシステムではなく、助成金対応の証跡を残すシステム。

重要なのはこの7つ。

1. 受講者ごとのID管理
2. 企業別マスターキーによる登録制限
3. LMSによる視聴・進捗ログ保存
4. 10時間以上・期間内修了の管理
5. 確認チェック・テスト・レポートによる修了判定
6. 修了証・LMS証跡・受講者一覧の出力
7. 協業先研修売上20%を基本にした成果報酬管理

成果報酬については、助成金受給額連動ではなく、協業先の研修売上に対するLMS開発・運用・証跡管理支援の対価として設計する。この形が、一番スピードも出せて、制度リスクも避けやすい。
