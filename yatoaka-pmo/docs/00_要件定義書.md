# やとアカ運営AI-PMOシステム 要件定義書

- **文書版数**: 第0.1版
- **作成日**: 2026年7月10日
- **対象組織**: やとアカ
- **先行導入対象**: イベント部会
- **システム区分**: 組織内部向けプロジェクト・業務管理システム

---

## 1．本書の目的

本書は、やとアカの理事、スタッフ、市役所・教育委員会の関係担当者が、部活動の地域展開に関する各種プロジェクトを一元的に管理するためのシステム要件を定義するものである。

本システムは、単なるタスク管理ツールではなく、以下の役割を持つ「やとアカの運営基盤」として構築する。

- 組織の理念、定款、中長期計画を保存する
- 部会・プロジェクト・会議・タスクを一元管理する
- 誰が、何を、いつまでに行うかを明確にする
- タスクの進捗を個人、部会、組織全体で可視化する
- 会議の目的、議題、決定事項、未完了事項を管理する
- AIが次回会議のアジェンダ、振り返り、リマインド案を提示する
- Google Drive上の資料を組織のナレッジとして活用する
- 理事やスタッフが迷わず利用できるUI・UXを提供する

## 2．システムの基本コンセプト

### 2.1 システム名称

仮称を以下とする。

> やとアカ運営AI-PMOシステム

PMOとは、組織内の複数プロジェクトを横断的に管理し、進捗、課題、会議、意思決定を支援する役割を指す。

### 2.2 システムが実現すること

本システムでは、組織の理念から日常業務までを、以下の流れでつなげる。

```
理念・定款・中長期計画
  ↓
年度方針・重点目標
  ↓
部会・プロジェクト
  ↓
親タスク・子タスク
  ↓
担当者・期限・進捗
  ↓
会議・振り返り・改善
```

すべてのプロジェクトやタスクについて、「どの組織目標を実現するための業務なのか」を関連付けられる構造とする。

### 2.3 AIの基本的な役割

AIは業務を勝手に実行するのではなく、人の意思決定と業務整理を支援する。

AIの役割は、以下の範囲とする。

- 情報の整理
- 会議資料の下書き
- 議事録の要約
- 決定事項の抽出
- タスク候補の抽出
- 未完了事項の抽出
- 次回アジェンダ案の作成
- タスク優先順位の提案
- 遅延理由の整理
- リマインド文面の作成
- 年間計画や中期計画との不整合の指摘
- ChatGPTへ渡すための情報・プロンプトの整形

AIは、原則として以下を自動実行しない。

- タスクの確定登録
- 担当者の確定
- 外部へのメール・LINE送信
- 会議の正式な招集
- 資料の外部公開
- 金銭や契約に関する承認
- 組織の意思決定

AIが作成した内容は、必ず人が確認して確定する。

## 3．対象範囲

### 3.1 システム利用者

初期段階の利用者は、以下とする。

- やとアカ理事
- やとアカ事務局スタッフ
- 各部会の部会長
- 各部会のメンバー
- 市役所・教育委員会の関係担当者
- 必要に応じて付与された内部協力者

### 3.2 対象外とする利用者

以下の関係者は、本システムへ直接ログインさせない。

- 学校の一般教職員
- 保護者
- 生徒・子ども
- 地域住民
- 協賛企業の担当者
- 一般の指導者
- イベント参加者

これらの外部関係者への情報発信は、公式LINE、Webサイト、紙資料、説明会等で行う。

本システムでは、外部関係者への対応状況、説明履歴、資料、次回アプローチ予定等を、内部管理情報として記録する。

### 3.3 初期導入対象

最初に実装・試行する対象は、イベント部会とする。

イベント部会で実際に運用し、使い勝手、入力負担、タスク粒度、リマインド頻度、会議フローを検証した後、他部会へ展開する。

## 4．組織・部会構成

本システムでは、以下の階層で組織を管理する。

### 4.1 組織階層

1. 総会
2. 理事会
3. 各部会
4. プロジェクト
5. 親タスク
6. 子タスク
7. 担当者の作業

### 4.2 部会構成

現時点では、以下の4部会を想定する。

| 部会 | 主な役割 |
| --- | --- |
| イベント部会 | キックオフイベント、体験会、説明会、交流会等の企画・運営 |
| 指導者研修・育成部会（仮称） | 指導者募集、研修、育成、指導方針、安全教育 |
| 方向性検討部会（仮称） | やとアカの理念、事業方針、中長期計画、地域展開戦略 |
| 財務部会 | 予算、収支、会費、補助金、協賛、寄付、財務管理 |

正式な部会名は、理事会等で別途確定する。

### 4.3 兼任管理

一人の理事やスタッフが複数部会を兼任できるようにする。

利用者ごとに以下を設定できるものとする。

- 所属部会
- 役職
- 部会長・副部会長・メンバーの区分
- 閲覧権限
- 編集権限
- 承認権限
- 通知対象

## 5．業務要件

### 5.1 ダッシュボード管理

ログイン後のホーム画面には、利用者に必要な情報だけを表示する。

**個人用ダッシュボード**

- 今日やるべきタスク
- 今週期限のタスク
- 期限超過タスク
- 自分が担当する親タスク・子タスク
- 自分が参加する次回会議
- 確認待ち・承認待ち事項
- AIからの提案
- 最近更新された資料
- 自分宛てのコメント・メンション

**部会用ダッシュボード**

- 部会全体の進捗率
- プロジェクト別進捗率
- 未着手・進行中・完了・遅延の件数
- 担当者別タスク状況
- 次回部会の日程
- 次回部会で確認すべき事項
- 部会のKPI
- 重要な未解決課題
- 最新の議事録
- AIによる部会状況の要約

**組織全体ダッシュボード**

- 全体進捗率
- 部会別進捗率
- 年度重点目標の達成状況
- 重要プロジェクトの進捗
- 期限超過タスク
- 意思決定待ち事項
- 部会横断課題
- 次回理事会・総会の論点候補
- 年間計画に対する進捗状況
- AIによる経営・運営上の注意点

### 5.2 プロジェクト管理

プロジェクトごとに以下の情報を管理する。

プロジェクト名 / 所属部会 / プロジェクト責任者 / 参加メンバー / プロジェクトの目的 / 背景 / 対象者 / 開始日 / 終了予定日 / ステータス / 優先度 / 進捗率 / 予算 / KPI / 関連する中期目標 / 関連する年度計画 / 関連資料 / 関連会議 / 関連ステークホルダー / リスク / 課題 / 決定事項

### 5.3 WBS・タスク管理

**タスク階層**

タスクは、以下の階層で管理する。

- プロジェクト
  - 親タスク
    - 子タスク
      - 必要に応じてチェック項目

例：

- キックオフイベント開催
  - 会場準備
    - 会場予約
    - レイアウト作成
    - 備品確認
  - 広報
    - チラシ原稿作成
    - 教育委員会確認
    - 印刷
    - 配布
  - 当日運営
    - スタッフ配置
    - 受付表作成
    - 緊急連絡網作成

**タスク管理項目**

各タスクに以下を登録する。

タスク名 / 親タスク / 所属プロジェクト / 所属部会 / 担当者 / 協力者 / 作成者 / 開始日 / 期限 / 優先度 / ステータス / 進捗率 / 完了条件 / 成果物 / 依存タスク / 関連資料 / コメント / リマインド設定 / 最終更新日時 / 更新者

**ステータス**

以下を基本ステータスとする。

未着手 / 対応中 / 確認待ち / 承認待ち / 保留 / 完了 / 中止

**進捗率**

進捗率は、以下の単位で表示する。

- 子タスクごとの進捗率
- 親タスクごとの進捗率
- プロジェクトごとの進捗率
- 部会ごとの進捗率
- 全体組織の進捗率

親タスクの進捗率は、原則として子タスクの進捗率から自動計算する。

初期段階では、以下のいずれかの計算方式を選択できるようにする。

1. 子タスクの単純平均
2. 子タスクごとの重み付け平均
3. 完了した子タスク数による算出

初期実装は、単純平均を基本とする。

### 5.4 カレンダー・スケジュール管理

以下の情報をカレンダー上に表示する。

タスクの開始日 / タスクの期限 / 会議予定 / イベント予定 / 資料提出期限 / 行政への提出期限 / 理事会・総会の日程 / 研修予定 / 説明会予定 / 重要マイルストーン

表示形式は以下に対応する。

月表示 / 週表示 / 日表示 / 担当者別表示 / 部会別表示 / プロジェクト別表示

将来的にはGoogleカレンダーとの連携を可能とする。

### 5.5 リマインド管理

システムは、登録された期限に応じてリマインド対象を抽出する。

**基本リマインド**

期限30日前 / 期限14日前 / 期限7日前 / 期限3日前 / 期限前日 / 期限当日 / 期限超過後

タスクごとに通知タイミングを変更できる。

**AIによるリマインド支援**

AIは、単なる期限通知ではなく、以下を含むリマインド案を作成する。

タスク名 / 担当者 / 期限 / 現在の進捗率 / 完了していない子タスク / 遅延による影響 / 次に行うべき作業 / 必要な確認相手 / 推奨する対応期限 / 担当者へ送る文面案

AIは通知文面を作成するが、自動送信は行わない。部会長または事務局が内容を確認し、必要に応じてLINE、メール、チャット等で送付する。

### 5.6 会議管理

**会議種別**

総会 / 理事会 / 部会 / プロジェクト会議 / 行政・教育委員会との打ち合わせ / 外部関係者との打ち合わせ / 振り返り会議

**会議情報**

会議名 / 会議種別 / 開催目的 / 開催日時 / 開催場所・オンラインURL / 参加者 / 主催者 / 議事録担当者 / 関連部会 / 関連プロジェクト / 関連タスク / 前回会議 / 次回会議 / アジェンダ / 配布資料 / 決定事項 / 保留事項 / タスク / 次回までの宿題

**会議前のAI支援**

会議開催前に、システムは以下の情報をまとめる。

前回会議の議事録 / 前回の決定事項 / 前回からの未完了タスク / 期限超過タスク / 次回までに確認が必要な事項 / 年間計画上この時期に決めるべき事項 / 関連プロジェクトの進捗 / 関係者からの未回答事項 / 次回アジェンダ案

AIは、議事録担当者に対して「次回会議では、以下のアジェンダで進めることを提案します」の形式で提案する。各アジェンダには、議題 / 議題の目的 / 確認事項 / 必要な決定 / 参照資料 / 想定時間 / 関係するタスク / 発言・説明担当候補 を表示する。

**会議後のAI支援**

議事録を登録すると、AIが以下を抽出する。

会議要約 / 決定事項 / 未決定事項 / 新規タスク候補 / 担当者候補 / 期限候補 / 継続審議事項 / 次回アジェンダ候補 / WBSの更新候補

抽出結果は「更新案」として表示し、人が確認後に登録する。

### 5.7 議事録テンプレート

議事録は、以下の共通形式を基本とする。

1. 会議名
2. 開催日時
3. 参加者
4. 会議の目的
5. アジェンダ
6. 各議題の内容
7. 決定事項
8. 未決定・保留事項
9. 新規タスク
10. 担当者
11. 期限
12. 次回までの宿題
13. 次回会議予定
14. 次回アジェンダ候補

議事録担当者が自由記述で作成した場合でも、システム側で上記形式に整理できることが望ましい。

### 5.8 ChatGPT連携用出力

初期段階では、すべてをAPI連携することを必須としない。システム内で必要な情報をまとめ、ChatGPTへ貼り付けられる形式で出力する機能を設ける。

**出力例**

次回会議アジェンダ作成用 / 議事録要約用 / 決定事項・タスク抽出用 / イベント企画書作成用 / 教育委員会向け報告資料作成用 / 理事会向け月次報告作成用 / 年間振り返り作成用 / リスク分析用 / 遅延タスク整理用

**出力内容**

組織の理念・方針 / 対象プロジェクト / 前回議事録 / 現在のWBS / 未完了タスク / 期限超過タスク / 決定事項 / 関係資料の要約 / ChatGPTへの依頼文

利用者は、生成された情報をコピーし、ChatGPTで深掘りや資料作成を行う。

### 5.9 組織ナレッジ管理

Google Driveを、やとアカの「組織の脳みそ」として活用する。

**保存対象**

定款 / 理念 / ミッション / ビジョン / 組織図 / 役員名簿 / 中期計画 / 年度計画 / 事業計画 / 予算書 / 総会資料 / 理事会資料 / 部会資料 / 議事録 / 教育委員会との協議資料 / 行政提出資料 / 活動マニュアル / 安全管理資料 / 指導者研修資料 / イベント企画書 / 報告書 / 協賛資料 / 契約書 / 過去の振り返り

**資料分類**

各資料には、以下の情報を付与する。

文書名 / 文書分類 / 作成日 / 更新日 / 作成者 / 対象年度 / 対象部会 / 対象プロジェクト / 公開範囲 / 正式版・下書きの区分 / 有効・廃止の区分 / 関連する組織目標 / Google DriveのURL

**重要文書の管理**

定款、理念、正式な事業計画等は「組織基準文書」として区分する。AIが提案を行う際は、日々の議事録だけでなく、組織基準文書を優先的に参照する。

### 5.10 ステークホルダー管理

本機能は営業CRMではなく、プロジェクト推進上の関係性と対応状況の管理を目的とする。

**ステークホルダー分類**

弥富市役所 / 教育委員会 / 学校 / 教職員 / 保護者 / 生徒 / 地域団体 / 指導者 / 地域企業 / 協賛企業 / 施設 / 競技・文化団体 / メディア / その他関係者

**管理項目**

組織名 / 担当者名 / 役職 / 連絡先 / 関係するプロジェクト / やとアカ側の担当理事 / 関係性 / 理解度 / 協力度 / 現在の依頼事項 / 相手側からの要望 / 最終面談日 / 次回接触予定 / 過去の打ち合わせ / 関連議事録 / 提供済み資料 / 次回提示資料 / 注意事項 / 対応ステータス

**AI支援**

AIは以下を提案する。

長期間連絡していない関係者 / 回答待ちの事項 / 次回説明時に必要な資料 / 相手ごとの説明ポイント / 関係構築上の注意事項 / 次にアプローチすべき関係者

## 7．UI・UX要件

### 7.1 レスポンシブ対応

PC、タブレット、スマートフォンの画面サイズに応じて、表示を自動調整する（レスポンシブWebデザイン）。PC版とスマートフォン版で別システムを作らず、同じシステムを利用できる構成とする。

**PCで重視する機能**: WBS一覧 / ガントチャート / 複数プロジェクト比較 / 詳細な会議資料作成 / 資料整理 / 部会・全体進捗確認 / 一括編集

**スマートフォンで重視する機能**: 今日のタスク確認 / タスク完了チェック / 進捗率更新 / コメント入力 / 写真・資料添付 / 会議予定確認 / リマインド確認 / 簡単な議事メモ / AI提案の閲覧

### 7.2 ホーム画面

ホーム画面では情報を詰め込みすぎず、以下を優先表示する。

1. 今日やること
2. 今週の期限
3. 遅れていること
4. 次回会議
5. AIからの提案

「最初に何をすればよいか」が一目で分かる画面とする。

### 7.3 操作性

- 主要操作は3クリック以内を目標とする
- 入力項目は必要最小限とする
- 選択式、チェック式を多用する
- ステータス変更を簡単にする
- スマートフォンで片手操作しやすくする
- 頻繁に使うボタンを画面下部に固定する
- 専門用語を減らす
- エラー内容を分かりやすく表示する
- 入力途中の自動保存を検討する
- 同じ情報を何度も入力させない

### 7.4 メニュー構成

スマートフォンでは、以下の下部固定メニューを基本とする。

ホーム / タスク / 会議 / 資料 / その他

PCでは左側メニューを基本とする。

ダッシュボード / プロジェクト / タスク / カレンダー / 会議 / 部会 / ステークホルダー / 資料 / KPI / AI支援 / 設定

### 7.5 色・表示ルール

色の使用は必要最小限とし、状態を直感的に判断できるようにする。

- 青：通常・進行中
- 緑：完了
- 黄：注意・確認待ち
- 赤：期限超過・重要課題
- 灰色：保留・中止

色だけに依存せず、文字やアイコンでも状態を表示する。

### 7.6 システム浸透のための要件

システムは、多機能であることよりも「迷わず使えること」を優先する。

- 初回利用時に簡単なガイドを表示する
- イベント部会で小さく始める
- 既存業務をすべて一度に変更しない
- 週次会議でシステム画面を実際に使う
- タスクの更新を会議運営の標準手順にする
- 入力担当者を曖昧にしない
- マニュアルは1ページ程度の簡易版を用意する
- 操作説明動画を用意する
- 利用者からの改善要望を記録する
- 使われていない機能は追加しない

## 10．権限管理要件

### 権限区分

| 権限 | 主な操作 |
| --- | --- |
| システム管理者 | 全設定、ユーザー、権限、データ管理 |
| 理事長・代表 | 全体閲覧、承認、全体方針管理 |
| 理事 | 全体閲覧、担当部会編集 |
| 部会長 | 担当部会のプロジェクト・タスク管理 |
| 部会メンバー | 担当タスクの閲覧・更新 |
| 事務局 | 会議、タスク、資料、通知の横断管理 |
| 行政関係者 | 許可された範囲の閲覧・コメント |
| 閲覧者 | 閲覧のみ |

### 権限の原則

- 必要な情報だけを閲覧できる
- 個人情報や財務情報は権限を限定する
- 誰がいつ変更したかを記録する
- 削除は原則として管理者のみとする
- 完全削除ではなくアーカイブを基本とする

## 11．非機能要件

### 11.1 利用環境

PCブラウザ対応 / スマートフォンブラウザ対応 / タブレット対応 / Chromeを推奨環境とする / 特別なアプリインストールを不要とする

### 11.2 性能

- ホーム画面は原則3秒以内に表示する
- タスク更新後、速やかに画面へ反映する
- 一覧表示は検索・絞り込みに対応する

### 11.3 セキュリティ

- Googleアカウント認証を使用する
- 権限のない利用者は閲覧できない
- 個人情報を一般公開しない
- 操作履歴を記録する
- 資料の共有設定を定期確認する
- 退任者・退職者の権限を速やかに停止する

### 11.4 バックアップ

- スプレッドシートの定期バックアップ
- Google Driveの重要資料の版管理
- 誤削除時の復元手順
- 月1回以上のバックアップ確認

### 11.5 保守性

- 項目や部会を管理画面から追加できる
- プログラム修正なしで選択肢を変更できる
- 年度切替に対応する
- 過去年度をアーカイブできる
- 担当者変更時にタスクを引き継げる

## 13．AI機能要件

### 13.1 今日のAI提案

ホーム画面に「今日のAI提案」を表示する。表示例：

- 期限が近いが進捗が低いタスク
- 担当者が設定されていないタスク
- 次回部会で確認すべき事項
- 教育委員会から回答待ちの事項
- 前回会議から更新されていないタスク
- イベント開催までに必要な次の作業

### 13.2 会議アジェンダ提案

AIは以下の情報からアジェンダ案を作成する。

会議の目的 / 前回議事録 / 未完了タスク / 期限超過タスク / 今後30日以内の予定 / 年度計画 / 中期計画 / 関連資料 / 関係者からの要望

### 13.3 振り返り支援

イベントや会議終了後に以下を整理する。

良かった点 / 問題点 / 原因 / 次回改善 / 継続すること / 廃止すること / 新規タスク候補 / 他部会へ共有すべき事項

### 13.4 組織方針との整合確認

AIは、タスクやプロジェクトが以下に沿っているかを確認する。

定款 / 理念 / 中期計画 / 年度方針 / 部活動地域展開の基本方針 / 理事会・総会の決定事項

不整合がある場合は、警告ではなく「確認提案」として表示する。

## 19．本システムの成功条件

本システムの成功は、機能数ではなく、以下の状態が実現したかで判断する。

- 誰が何をするかが明確になっている
- 理事やスタッフが自分のタスクをすぐ確認できる
- 部会長が進捗を追いかけやすい
- 会議前の資料準備が短時間で済む
- 議事録からタスクが漏れなく整理される
- 未完了タスクが放置されない
- 総会・理事会と日常業務がつながっている
- 組織の理念や中期計画から業務がずれにくい
- Google Drive内の資料を探す時間が減る
- イベント部会で定着し、他部会へ展開できる
- 利用者が「便利」より先に「迷わない」と感じる
- システムを開けば、今日やるべきことが分かる

## 20．結論

本システムは、やとアカの内部業務を一元管理するためのAI支援型PMOシステムとして構築する。

初期段階では、Google Drive、スプレッドシート、ドキュメント、カレンダー、Google Apps Scriptを活用し、低コストかつ短期間でイベント部会向けの試作版を立ち上げる。

AIには、業務の自動実行を求めず、会議準備、議事録整理、タスク抽出、進捗分析、リマインド案、次回アジェンダ案の作成を担当させる。

まずイベント部会で実際の業務を回し、「毎日使える」「迷わない」「会議とタスクがつながる」ことを確認したうえで、指導者研修・育成部会、方向性検討部会、財務部会、理事会、総会へ段階的に展開する。
